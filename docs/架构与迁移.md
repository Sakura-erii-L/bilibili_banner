# GitHub 与 NAS 的边界

## v11 迁移结论（2026-08-31）

现已从“DOM-first + 多点实测”迁移为“API-first + Archive fallback + DOM verify-only”。旧 archive 无需重写；新 archive 使用 v11 API 参数模型。后续迁移应优先扩展 provider/renderer，不要把默认路径改回对官方参数的重复实测。

## 核心层

以下内容与部署平台无关：

```text
backend/capture.py
frontend/
data/
scripts/build_site.py
```

## GitHub 专属层

只有：

```text
.github/workflows/
```

负责：

- 定时
- CI 环境
- 自动 commit
- GitHub Pages deploy

## NAS 专属层

以后可增加：

```text
deploy/nas/
├─ nginx.conf
├─ docker-compose.yml
└─ cron
```

不需要修改 `backend/capture.py` 或前端数据格式。

因此 GitHub Pages 是当前的托管方式，不是项目架构本身。
