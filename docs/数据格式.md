# 数据格式（v9.2）

本文档描述 `backend/capture.py` 实际读写的 JSON 和归档目录。路径示例以项目根目录为基准；如果设置 `BANNER_DATA_DIR`，根目录会被替换为该目录。

## 1. 数据目录

```text
data/
├─ index.json                         # 前端入口
├─ current/                           # 最近一次被接受的唯一内容
│  ├─ banner.json
│  ├─ layer_00_<sha1前10位>.*
│  └─ static.*
├─ archive/
│  └─ <日期_时间_contentHash>/
│     ├─ banner.json
│     ├─ layer_00_<sha1前10位>.*
│     └─ static.*
└─ diagnostic.json                    # 失败诊断，默认不提交
```

`data/current/` 只在非重复内容被接受时替换为最新工作副本。当前内容或历史中已有的素材再次出现时，抓取器完全不改写 `current/`、`archive/` 和 `index.json`；历史归档不会因为日常更新被删除。

新版本不生成 `preview.png`。旧归档中如果仍有该文件，或数据目录中存在 `diagnostic.json`、`.capture_*`、`.current_old`，`scripts/build_site.py` 都会在发布构建时排除它们。

## 2. `data/index.json`

索引由 `rebuild_index()` 根据所有归档目录中的 `banner.json` 重建，结构如下：

```json
{
  "version": 9.2,
  "generatedAt": "2026-08-30T22:11:09+08:00",
  "records": [
    {
      "id": "2026-08-30_221101_a6c4f537bffba395ff453d64",
      "date": "2026-08-30",
      "year": "2026",
      "month": "08",
      "yearMonth": "2026-08",
      "season": "summer",
      "capturedAt": "2026-08-30T22:11:01+08:00",
      "mode": "split",
      "layerCount": 28,
      "contentHash": "a6c4f537bffba395ff453d64",
      "manifest": "./data/archive/2026-08-30_221101_a6c4f537bffba395ff453d64/banner.json"
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | number | 当前为 `9.2` |
| `generatedAt` | string | 重建索引时的本地时区 ISO 时间 |
| `records` | array | 按 `capturedAt` 倒序、按 `contentHash` 去重后的历史记录 |
| `id` | string | 归档目录名 |
| `date` | string | `YYYY-MM-DD` 抓取日期 |
| `year` | string | 从 `date` 派生的年份 |
| `month` | string | 两位月份 |
| `yearMonth` | string | `YYYY-MM` |
| `season` | string | `spring`、`summer`、`autumn`、`winter` |
| `capturedAt` | string | manifest 的抓取时间 |
| `mode` | string | `split` 或 `static` |
| `layerCount` | number | manifest 中 `layers` 的数量；静态模式通常为 `0` |
| `contentHash` | string | 内容指纹前 24 位 |
| `manifest` | string | 供前端解析的相对 URL |

索引不再包含 `preview` 字段。前端只使用 `manifest`，资源路径由前端以 manifest 所在目录为基准解析。

季节映射来自 `season_of()`：

```text
3、4、5月   → spring
6、7、8月   → summer
9、10、11月 → autumn
12、1、2月  → winter
```

## 3. 归档目录命名

```text
YYYY-MM-DD_HHMMSS_<contentHash>
```

例如：

```text
2026-08-30_221101_a6c4f537bffba395ff453d64
```

其中时间使用 `BANNER_TIMEZONE`，默认是 `Asia/Shanghai`；同一素材重复出现不会自动新建目录，除非使用 `--force`。

## 4. `banner.json` 顶层字段

```json
{
  "version": 9.2,
  "capturedAt": "2026-08-30T22:11:01+08:00",
  "date": "2026-08-30",
  "season": "summer",
  "source": {},
  "viewport": {"width": 1650, "height": 800},
  "banner": {"x": 0, "y": 0, "width": 1650, "height": 155},
  "mode": "split",
  "static": {},
  "layers": [],
  "interaction": {},
  "contentHash": "a6c4f537bffba395ff453d64"
}
```

| 字段 | 说明 |
| --- | --- |
| `version` | manifest 数据版本，目前为 `9.2` |
| `capturedAt` | 带时区的抓取时间 |
| `date` | 抓取日期 |
| `season` | 由抓取月份计算的季节 |
| `source` | 来源页面和抓取方式 |
| `viewport` | Headless 浏览器视口尺寸 |
| `banner` | `.animated-banner.getBoundingClientRect()` 的几何信息 |
| `mode` | `split` 表示分层重建；`static` 表示显示原始静态图 |
| `static` | Bilibili 原始静态图信息；split manifest 中也可能存在，但 split 前端优先使用 layers |
| `layers` | 分层媒体及交互参数数组 |
| `interaction` | 前端交互模型和回位配置 |
| `contentHash` | 由归档文件内容计算出的去重键 |

### 4.1 `source`

```json
{
  "page": "https://www.bilibili.com/",
  "resolvedUrl": "https://www.bilibili.com/",
  "captureMethod": "hidden-rendered-homepage-dom"
}
```

`resolvedUrl` 记录两次导航后页面的最终 URL；如果页面被重定向，可能与 `page` 不同。

### 4.2 `static`

抓取器从以下选择器中寻找原始图片：

```text
picture.banner-img img
.bili-header__banner picture img
.bili-header__banner > img
```

成功时会保存 `src`、原始尺寸、`objectFit`、`objectPosition` 和本地 `file`。它是页面原始图片，不是截图。

### 4.3 `interaction`

当前结构：

```json
{
  "model": "bilibili-moveX-times-a",
  "positionAxis": "x-only",
  "effects": ["translateX"],
  "returnDurationMs": 300
}
```

## 5. `layers[]` 字段

示例：

```json
{
  "index": 3,
  "tag": "img",
  "src": "https://i0.hdslb.com/bfs/vc/example.png@1c.webp",
  "file": "layer_03_b933bdd3c3.webp",
  "contentType": "image/webp",
  "width": 1690,
  "height": 158,
  "naturalWidth": 3840,
  "naturalHeight": 360,
  "objectFit": "cover",
  "objectPosition": "50% 50%",
  "transformOrigin": "844.75px 79.1953px",
  "transform": [1, 0, 0, 1, 0, 2.2],
  "opacity": [1, 1],
  "a": 0.0013333300352096557,
  "captureTargetTag": "img"
}
```

| 字段 | 说明 |
| --- | --- |
| `index` | 原始 `.layer` 的顺序，从 `0` 开始 |
| `tag` | 媒体标签，当前主要是 `img` 或 `video` |
| `src` | 抓取时页面解析出的媒体地址，仅作溯源 |
| `file` | 归档目录中的本地文件名，前端使用它 |
| `contentType` | 下载响应的 MIME 类型 |
| `width` / `height` | 抓取视口下的 CSS/DOM 显示尺寸 |
| `naturalWidth` / `naturalHeight` | 图片原始尺寸或视频尺寸 |
| `objectFit` / `objectPosition` | 媒体原始显示方式 |
| `transformOrigin` | 目标元素的 transform origin |
| `transform` | 初始二维 CSS matrix，顺序为 `[a,b,c,d,e,f]` |
| `opacity` | `[layerOpacity, mediaOpacity]` |
| `a` | 水平运动系数，前端使用 `initialX + moveX * a` |
| `captureTargetTag` | 实际读取 transform 的 `firstElementChild` 标签 |

CSS matrix 的关键位置：

```text
[a, b, c, d, e, f]
             │  │
             │  └─ Y 位移（前端交互不改）
             └──── X 位移（前端交互只改这一项）
```

初始 matrix 可以包含原始布局产生的 Y、scale 或其他二维变换信息；“只水平交互”表示鼠标回放阶段只修改 X，不表示初始素材不存在 Y 或缩放。

## 6. `contentHash` 规则

分层模式包含每个已下载图层的：

```text
index、tag、文件 SHA-256、文件大小、naturalWidth、naturalHeight
```

静态模式包含静态文件的 SHA-256 和文件大小。组合后的 JSON 使用稳定排序，再计算 SHA-256，截取前 24 位。

因此 URL 查询参数、抓取时间、transform 和 `a` 不参与去重。修改这些元数据而不修改素材内容，不会自动形成新的历史记录。

## 7. `diagnostic.json`

失败诊断由 `save_diagnostic()` 写入 `data/diagnostic.json`，可能包含：

```json
{
  "capturedAt": "2026-08-30T22:11:01+08:00",
  "reason": "all-layer-horizontal-motion-is-zero",
  "url": "https://www.bilibili.com/",
  "title": "...",
  "animatedCount": 1,
  "layerCount": 28,
  "before": [],
  "after": []
}
```

常见 `reason`：

- `animated-banner-not-found`
- `layer-count-changed-during-motion-probe`
- `all-layer-horizontal-motion-is-zero`

该文件默认被 `.gitignore` 忽略，因为它可能包含页面诊断信息；排障时可在本地保留并查看。
