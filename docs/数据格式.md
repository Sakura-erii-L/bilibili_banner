# 数据格式（v11 结构化归档，兼容 v9/v10）

## v11 数据格式补充（2026-08-31）

v11 分层 layer 新增 `resources[]`、`apiConfig`、`apiLayer`、`apiIndex`；manifest 新增 `api` 摘要，完整响应保存到 `source/api.json`。一个 layer 可包含多份带 `duration`（毫秒）的资源。分层 Banner 的 `static`/`pic` 只作为 `fallback_image`。`interaction.model` 为 `bilibili-header-api-v1` 时，前端直接按官方参数计算而不是读取 9 点采样曲线；palxiao 使用独立的 `palxiao-reconstructed-v1`，不代表官方 `split_layer`。

本文以 `backend/capture.py`、`backend/wayback_import.py` 和 `frontend/app.js` 的当前实现为准。旧 v9.2/v10 manifest 仍可回放，但缺少新字段时只能视为 `unverified`，不能据此证明原 Banner 确实是静态图。

## 1. 一个 archive 的目录

```text
data/archive/<日期_时间_contentHash>/
├─ banner.json
├─ static.*                         # 真实单图/单视频主体，或 layered 的 fallback
├─ layer_00_*.*                     # 每层一个原始文件
├─ layer_01_*.*
└─ source/
   ├─ page.html                     # Banner 根 DOM
   ├─ styles.css                    # 相关内联 CSS 证据
   ├─ script.js                     # 相关内联脚本证据，前端不执行
   ├─ api.json                      # Header API 原始响应（如有）
   └─ palxiao-data.json             # palxiao 原始 data.json（如有）
```

文件不存在表示归档页未提供该类证据，不会创建空截图替代。`preview.png` 不属于 Banner 主数据，也不会进入 Pages 发布物。

## 2. 顶层 manifest

```json
{
  "version": 11.0,
  "capturedAt": "2026-08-31T18:17:00+08:00",
  "date": "2026-08-31",
  "season": "summer",
  "type": ["layered", "video", "interactive"],
  "mode": "split",
  "is_split_layer": true,
  "fallback_image": "static.webp",
  "preview_image": null,
  "completeness": "partial",
  "missing_assets": ["interaction.js"],
  "viewport": {"width": 1650, "height": 800},
  "banner": {"x": 0, "y": 0, "width": 1650, "height": 155},
  "static": {},
  "layers": [],
  "interaction": {},
  "assets": [],
  "structureEvidence": {},
  "animationCss": "@keyframes ...",
  "sourceFiles": {"html": "source/page.html"},
  "hashes": {
    "resourceHash": "...",
    "structureHash": "...",
    "interactionHash": "...",
    "contentHash": "...",
    "canonicalContentHash": "...",
    "sourceFingerprint": "..."
  },
  "contentHash": "...",
  "canonicalContentHash": "...",
  "sourceFingerprint": "...",
  "layoutHash": "...",
  "familyId": "...",
  "observedSlots": [1080],
  "observations": []
}
```

`type` 是兼容字段，值为数组但字段名必须保持 `type`，不是 `types`。它不是互斥枚举：

- `static`：原始 Banner 经证据确认只有一个静态图片/SVG。
- `layered`：存在多个独立媒体或 `.animated-banner .layer`。
- `animated`：存在 CSS/SVG/图片动画或 canvas 动态证据。
- `video`：存在 `<video>`、WebM、MP4 或 M3U8 线索；真实 `video.src`/`source src` 优先，poster 只能作为 preview/fallback。
- `interactive`：采样到交互效果，或源证据表明存在交互但参数缺失。

`mode` 保留给旧前端兼容；新代码优先读取 `type`。

## 3. 完整性和 fallback

- `complete`：检测到的主要结构和资源均已保存。
- `partial`：至少一个图层、视频、关键帧、canvas/WebGL 逻辑或交互参数缺失。
- `unverified`：旧 manifest 或缺少足够结构证据。

layered Banner 中的 `static.file` 只对应 `fallback_image`，不参与该 Banner 的主要资源哈希。前端优先级是：可用 layers/video -> partial layers -> 原始 fallback；永远不会自动显示 preview 截图。只有保存了真实视频文件时，视频才能成为主资源；poster 不会被当成图片主资源。

## 4. `layers[]`

```json
{
  "index": 3,
  "tag": "video",
  "assetType": "video",
  "src": "原始或归档资源 URL",
  "file": "layer_03_effect.webm",
  "contentType": "video/webm",
  "width": 1690,
  "height": 158,
  "naturalWidth": 3840,
  "naturalHeight": 360,
  "position": {
    "type": "absolute",
    "left": "0px",
    "top": "0px",
    "right": "auto",
    "bottom": "auto"
  },
  "zIndex": 3,
  "objectFit": "cover",
  "objectPosition": "50% 50%",
  "transformOrigin": "50% 50%",
  "transform": [1, 0, 0, 1, 0, 2.2],
  "opacity": [1, 1],
  "animation": {
    "name": "cloudMove",
    "duration": "8s",
    "delay": "0s",
    "iterationCount": "infinite",
    "timingFunction": "linear"
  },
  "animationTarget": "target",
  "motion": {
    "matrixDelta": [[0, 0, 0, 0, -10, 1], [0, 0, 0, 0, 14, -2]],
    "layerOpacityDelta": [0, 0],
    "mediaOpacityDelta": [-0.1, -0.2],
    "returnRemaining": [1, 0.31, 0]
  }
}
```

前端创建 `.layer > .motion > img|video`。z-index/层透明度放在 `.layer`；target transform、position 和 transform-origin 放在 `.motion`；媒体透明度和媒体动画放在 IMG/VIDEO。各层始终是独立 DOM，不进行合成。

## 5. 交互协议

```json
{
  "model": "bilibili-sampled-horizontal-v1",
  "positionAxis": "observed",
  "inputMode": "relative-from-pointer-enter",
  "inputSamplesPx": [-1600, -1200, -800, -400, 0, 400, 800, 1200, 1600],
  "effects": ["matrix", "translateX", "translateY", "opacity"],
  "returnSamplesMs": [0, 16, 33, 50, 75, 100, 150, 225, 325],
  "returnDurationMs": 325,
  "samplingViewportWidth": 1650
}
```

采样输入是指针进入后的水平差值。输出不是手写 `moveX * a` 的统一特效，而是 Bilibili 页面脚本实际产生的完整 `[a,b,c,d,e,f]` matrix、层透明度和媒体透明度。由水平输入引起的 scale、rotate、translateX、translateY 都会保留。旧 manifest 没有 `motion` 时才使用 `a` 兼容。

## 6. 结构证据

`structureEvidence` 保存：

- Banner root、`.layer` 数量、可见媒体数量。
- IMG/VIDEO/SOURCE/SVG/CANVAS 的 src/srcset/source、data-* 和 computed CSS。
- performance 资源 URL、stylesheet URL、script URL。
- `is_split_layer/split_layer/layers`、video、canvas、SVG、CSS animation 和 interaction 信号。
- 仅抽取的 `@keyframes`，避免把整页 CSS 注入前端。

若 `is_split_layer == 1` 或存在多个媒体，`capture_static()` 不会选择第一个 IMG 作为完整 Banner。没有标准 `.layer` 时，`capture_structured_media()` 会逐个保存可恢复媒体。

## 7. 去重

```text
每个主要资源 SHA-256 -> resourceHash
图层顺序、几何、matrix、position、animation、类型、keyframes/CSS 证据 -> structureHash
interaction + 每层 motion/animation -> interactionHash
三者组合 -> contentHash
```

只有资源、结构、动画和交互都相同才视为同一版本。检测到交互但无法采样时，相关脚本/JSON 证据会额外参与 `interactionHash`，避免把未知逻辑强行合并；已有真实采样时不使用整段脚本哈希，避免页面动态状态制造重复。日期、远程 URL、`observedSlots` 和 `familyId` 不参与旧内容去重。layered 的 fallback 图片也不参与主要资源哈希。

`canonicalContentHash` 只使用规范化后的保存资源 bytes、媒体类型、图层顺序/几何/opacity 等结构，不使用 provider、API 原始对象或 interaction model，可用于谨慎的跨 Provider 比较。`sourceFingerprint` 则包含 provider、来源标识、交互 model 和相关 source hash，用于保留来源差异；未经证据确认时不得据此合并不同 Provider 的图层。

旧 archive 没有这些哈希时，审计会给出 legacy warning；程序不能凭旧静态文件反推其原始页面没有其它图层。

## 8. `data/index.json`

索引中的 record/variant 包含 `type`、`mode`、`layerCount`、`completeness`、`missing_assets`、`contentHash`、可选 `canonicalContentHash` 和 manifest 相对路径。`variants[]` 表示同一 family 在不同上海时间槽观察到的真实版本，前端按最近 `observedSlots` 选择。

## 9. 自动审计

```powershell
python scripts\audit_archives.py
```

以下情况是硬错误：

- layered 但没有任何 layer。
- 多 layer/video 证据最终只剩静态图片。
- manifest 引用的 layer/static 文件不存在。
- 新 `hashes` 与实际文件或结构不一致。

`--strict` 还会把 legacy 缺字段 warning 当作失败。
