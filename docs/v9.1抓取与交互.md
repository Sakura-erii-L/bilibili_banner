# v9.1 抓取与交互说明

## 1. 为什么后台仍然需要浏览器引擎

项目需要获得“当前 Bilibili 首页真正渲染的 Banner”，而不是一个可能滞后的 Header API 返回值。

因此后台仍会：

```text
Playwright
   ↓
Headless Chromium / Edge / Chrome
   ↓
https://www.bilibili.com/
   ↓
读取 .animated-banner .layer
```

这里的“打开网页”仅发生在后台无界面浏览器进程中。

不会：

- 弹出 Edge/Chrome 窗口
- 抢占桌面
- 显示 Bilibili 页面
- 让前端访问 Bilibili

## 2. 为什么上一版可能完全没有交互

已知 Bilibili Banner 抓取实现读取的是：

```text
.layer.firstElementChild.style.transform
```

上一版为了兼容复杂 DOM，优先查找了内部 `img/video` 的 transform。

如果实际移动 transform 位于它的外层 `firstElementChild`，就会出现：

```text
真实图层在动
        ↓
抓取器读到里面不动的 img
        ↓
horizontalMotion = 0
        ↓
本地所有图层不动
```

v9.1 已修正为以 `firstElementChild` 为运动对象。

## 3. 交互公式

后台：

```text
初始 X = x0
鼠标横移 D
移动后 X = x1

a = (x1 - x0) / D
```

前端：

```text
moveX = mouseX - enterX
layerX = initialX + moveX * a
```

这是每层独立计算的。

因此：

```text
layer 0: a = 0
layer 1: a = 0.01
layer 2: a = 0.03
layer 3: a = -0.015
```

会自然形成不同方向、不同速度的水平视差。

## 4. Y 轴

交互代码只修改 CSS matrix 的 `e`（X）：

```text
m[4] = initialX + moveX * a
```

不会修改 `m[5]`（Y）。

因此鼠标移动不会造成上下漂移。

## 5. 抓取保护

如果实际抓取后：

```text
max(abs(a)) <= 1e-6
```

程序会停止并写：

```text
data/diagnostic.json
```

不会把无交互结果加入归档。
