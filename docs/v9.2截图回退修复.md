# v9.2 截图回退修复

v9.1 曾在 `loadEntry()` 捕获异常后自动显示 `preview.png`。
这会导致任何分层路径或资源问题最终表现为“一张没有交互的截图”。

v9.2 已彻底删除这个回退。

## 硬性规则

分层 Banner：

```text
banner.json
+ layer_00...
+ layer_01...
+ ...
```

必须成功加载并重建。

如果失败：

```text
直接显示“分层素材载入失败”
```

绝不使用截图代替。

## 后端

`backend/capture.py` 不再调用 Banner screenshot。

## GitHub Pages

`scripts/build_site.py` 使用：

```python
shutil.ignore_patterns(
    "preview.png",
    "diagnostic.json",
    ".capture_*",
    ".current_old",
)
```

即使旧归档中残留 `preview.png`，也不会进入 `_site` 发布物。

## 与 static 模式的区别

`static` 模式保存的是 Bilibili 页面自己引用的原始静态图片文件，
不是浏览器对页面进行的截图。
